🧠 LLM 上下文管理

理解 AI 智能体如何处理和利用上下文信息

📖 什么是 LLM 上下文？

定义与重要性

Context（上下文）是指 LLM 在生成回复时所参考的所有信息，包括：

  • 系统提示词（System Prompt）：定义 AI 的角色、能力和行为准则
  • 用户输入（User Input）：当前对话中的用户消息
  • 历史对话（Conversation History）：之前的交互记录
  • Skill 定义（SKILL.md）：工作流程和输出模板
  • 知识库内容（Knowledge Base）：领域专业知识
  • 工作记忆（Working Memory）：当前任务的状态和中间结果
💡 为什么上下文很重要？
上下文质量直接决定了 AI 输出的准确性和相关性。在统计学习中， 完整的上下文可以帮助 AI：
  • 理解用户的真实学习需求（而不只是字面意思）
  • 选择合适的解释深度和表达方式
  • 关联相关概念，构建知识网络
  • 避免重复已解释过的内容
  • 记住用户的偏好和学习进度

🧩 上下文的组成结构

层级 类型 内容示例 作用
L0 系统 System Prompt "你是一个统计学教学助手..." 定义角色和行为边界
L1 Skill SKILL.md 内容 概念学习模板、输出格式规范 指导工作流程和输出结构
L2 知识 领域知识库 统计公式、定理、代码库 提供专业、准确的内容
L3 对话 历史消息 "之前学习了正态分布..." 保持对话连贯性
L4 输入 当前用户输入 "帮我学习假设检验" 触发具体的任务执行

🪟 上下文窗口管理

Token 限制与优化策略

LLM 的上下文窗口有固定的 Token 限制（例如 4K/8K/32K/128K）。对于复杂的统计学习任务，需要智能地管理上下文空间：

# 上下文窗口分配策略（以 8K 窗口为例） class ContextManager: def __init__(self, max_tokens=8192): self.max_tokens = max_tokens self.allocation = { "system_prompt": 500, # 固定：系统提示 "skill_definition": 1500, # 固定：Skill模板 "knowledge_base": 2000, # 动态：相关知识片段 "conversation_history": 3000, # 滚动：最近N轮对话 "user_input": 500, # 当前输入 "output_buffer": 692 # 预留给输出 } def optimize_context(self, user_query): # 1. 意图识别 intent = self.recognize_intent(user_query) # 2. 检索相关知识（按相关性排序） knowledge = self.retrieve_knowledge( query=user_query, max_tokens=self.allocation["knowledge_base"] ) # 3. 压缩历史对话（保留摘要+最近3轮） history = self.compress_history( keep_last_n=3, summarize_older=True ) # 4. 组装最终上下文 context = { "system": self.system_prompt, "skill": self.skill_template, "knowledge": knowledge, "history": history, "input": user_query } return context
⚠️ 关键挑战：
  • 长尾问题：复杂统计概念的完整解释可能超过窗口限制
  • 信息优先级：如何决定哪些知识更重要？
  • 动态调整：根据查询类型重新分配 Token 配额

💡 实际应用示例

示例：用户询问 "中心极限定理"

=== 构建的完整上下文 === [SYSTEM] 你是一个专业的统计学教学AI助手。你的任务是帮助学生理解... （系统提示词 - 500 tokens） [SKILL CONTEXT] ## Skill: concept-learning-generator ### 触发条件 当用户提出以下需求时触发此 Skill： - "帮我学习XXX概念" - "解释一下统计学中的XXX" ... （SKILL.md 核心内容 - 1200 tokens） [KNOWLEDGE RETRIEVED] **主题**: Central Limit Theorem (CLT) **数学定义**: 设 X₁, X₂, ..., Xₙ 是独立同分布的随机变量... **直观解释**: 当样本量足够大时，样本均值的分布近似正态分布... **关键公式**: $$\bar{X} \sim N(\mu, \sigma^2/n)$$ **Python 示例**: 使用 numpy 模拟 CLT 的代码... **常见误区**: CLT 不要求原始数据服从正态分布... **前置知识**: 随机变量、期望值、方差、正态分布 **应用场景**: 置信区间估计、假设检验... （相关知识片段 - 1800 tokens） [CONVERSATION HISTORY] User: 我正在学习统计学基础 Agent: 很好！统计学是数据分析的基础。你想从哪个主题开始？ User: 刚学完描述性统计，想了解概率分布 Agent: 正态分布是最重要的概率分布之一。需要我详细讲解吗？ （最近3轮对话 - 800 tokens） [CURRENT INPUT] User: 帮我学习中心极限定理 （当前输入 - 50 tokens） === 总计: ~4350 tokens (剩余空间用于输出) ===
✅ 上下文优化的效果：
  • AI 知道用户已经学了描述性统计 → 跳过基础铺垫
  • 知道用户想了解概率分布 → 重点强调 CLT 与正态分布的关系
  • 检索到完整的 CLT 知识 → 可以生成高质量的解释
  • 有 SKILL 模板 → 输出结构化、格式统一

💾 上下文持久化与记忆

跨会话的上下文管理

为了提供连续的学习体验，系统实现了多层记忆机制：

记忆层 存储位置 生命周期 存储内容
工作记忆 当前会话 临时（会话结束即清除） 当前任务的中间状态、计算过程
短期记忆 Workspace Memory (.workbuddy/memory/) 当天 今日学习进度、生成的资料路径
长期记忆 MEMORY.md 文件 永久 用户偏好、学习风格、薄弱环节
项目记忆 Git 仓库历史 版本化管理 所有生成的学习资料、练习题

✨ 上下文管理的最佳实践

针对统计学习的优化建议

  1. 分层加载知识
    先加载核心定义，再根据用户追问深入细节（避免一次性加载过多）
  2. 使用结构化模板
    SKILL.md 定义的模板确保输出一致性，减少上下文中的格式说明
  3. 主动总结长对话
    每5-10轮自动生成摘要，释放上下文空间
  4. 标记数学符号
    首次引入符号时明确定义，后续可直接使用（节省重复解释）
  5. 保存中间状态
    复杂推导过程可分步进行，每步结果存入工作记忆
  6. 利用文件系统
    大型代码示例或数据集通过文件引用，而非内嵌到上下文中
🔧 技术实现提示：
  • 使用向量数据库（如 FAISS）进行语义检索相关知识
  • 实现 Token 计数器，实时监控上下文使用量
  • 设计上下文优先级队列，确保关键信息不被截断
  • 考虑使用上下文压缩模型（如 LongChat）处理超长历史
